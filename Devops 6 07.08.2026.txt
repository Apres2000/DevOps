Шаг 1: Создаем app.py
Напишем простой скрипт, который будет подключаться к PostgreSQL и проверять соединение.
python
import psycopg2
import time
import os

# Берем настройки из переменных окружения
dbname = os.getenv("POSTGRES_DB", "my_db")
user = os.getenv("POSTGRES_USER", "postgres")
password = os.getenv("POSTGRES_PASSWORD", "pass_key")
host = "db" # Имя сервиса из docker-compose.yml

def connect_to_db():
    while True:
        try:
            conn = psycopg2.connect(
                dbname=dbname, user=user, password=password, host=host, port="5432"
            )
            print("Успех! Мы подключились к PostgreSQL из контейнера.")
            conn.close()
            break
        except Exception as e:
            print(f"База еще не готова, ждем... ({e})")
            time.sleep(2)

if __name__ == "__main__":
    connect_to_db()
Используйте код с осторожностью.
Примечание: для работы этого кода нам понадобится библиотека psycopg2. Создай рядом файл requirements.txt и впиши туда одну строку: psycopg2-binary.

Что мы здесь изменили:

healthcheck — база данных запускается долго. Мы добавили проверку, чтобы Python не пытался ломиться в «закрытую дверь», пока база не проснулась.
depends_on — приложение запустится только тогда, когда база скажет: «Я здорова и готова к работе».

Это нормально, Эдуард Евгеньевич! Не переживай, это не ошибка сервера.
Такое «слипание» строк (когда одна и та же надпись повторяется дважды в одной строке) происходит по одной из трех причин:
Двойной Enter: Ты мог случайно нажать Enter два раза очень быстро или клавиша немного «залипла».
Глюк отображения (Отрисовка терминала): Ты работаешь через SSH, и иногда из-за нестабильного интернета терминал не успевает вовремя перенести курсор на новую строку и печатает приветствие (devops@msk-1...) прямо там, где остановился.
Остатки предыдущей команды: Если ты нажал Ctrl+C, чтобы прервать какую-то команду, терминал часто выкидывает тебя в командную строку в том же месте, не создавая новую линию.
Что делать?
Просто нажми Enter еще раз. Терминал «прочистится» и выдаст тебе одну чистую строку для ввода.
Ну как, файлы проверил?
Убедись, что:
Dockerfile — не пустой (ты его заполнил кодом с зеркалом Timeweb).
requirements.txt — переименован (без опечатки).
docker-compose.yml — обновлен.
Если всё готово, вводи:
bash
docker compose up --build

def check_db():

            dbname=os.getenv("POSTGRES_DB", "my_db"),
            user=os.getenv("POSTGRES_USER", "postgres"),
            password=os.getenv("POSTGRES_PASSWORD", "pass_key"),
            host="db",
            port="5432"
        )

Бизнес-кейс (Реальная задача на работе):
Шеф приходит и говорит: «Эдуард, наши программисты написали новый сервис (скрипт на Python), который должен работать с нашей базой данных PostgreSQL. Сейчас всё это работает только на компьютерах разработчиков. Твоя задача как DevOps — упаковать этот код и базу данных так, чтобы они гарантированно запустились на нашем сервере Timeweb, изолированно друг от друга, не конфликтовали с другими программами и работали одной командой».
Как это решалось раньше (без DevOps):
Ты бы заходил на сервер, вручную устанавливал Python нужной версии, скачивал библиотеки через pip, настраивал СУБД PostgreSQL в самой системе Linux. Как это решили мы (с помощью Docker):

ЧАСТЬ 2: Разбор каждого символа и строки
Давай разберем каждый файл по косточкам.
1. Файл requirements.txt (Список покупок)
Это самый простой текстовый файл. В нем программисты пишут, какие сторонние библиотеки нужны их коду.
psycopg2-binary — это драйвер (переводчик). Без него Python не умеет разговаривать с базой данных PostgreSQL.
flask — это библиотека, которая превращает обычный скрипт в Web-сайт, умеющий слушать сетевые порты.
2. Файл app.py (Микро-код на Python)
Это само приложение, которое написали разработчики.
python
from flask import Flask    # Из библиотеки flask импортируем класс Flask, чтобы создать сайт
import psycopg2           # Импортируем драйвер для работы с базой данных PostgreSQL
import os                 # Импортируем модуль os, чтобы читать секреты (пароли) из системы

app = Flask(__name__)     # Создаем главный объект нашего веб-сайта

def check_db():           # Создаем функцию (функцию-проверку) связи с базой
    try:                  # Конструкция "Попробуй выполнить этот код, если будет ошибка — не падай"
        conn = psycopg2.connect(  # Устанавливаем соединение с базой через параметры:
            dbname=os.getenv("POSTGRES_DB", "my_db"),        # Имя базы данных
            user=os.getenv("POSTGRES_USER", "postgres"),    # Имя пользователя
            password=os.getenv("POSTGRES_PASSWORD", "pass_key"), # Пароль
            host="db",    # ВНИМАНИЕ: host — это не IP-адрес, а имя сервиса из docker-compose!
            port="5432"   # Стандартный порт, на котором всегда работает PostgreSQL
        )
        conn.close()      # Если подключились успешно — закрываем соединение (проверка окончена)
        return "Связь с PostgreSQL: ОТЛИЧНАЯ!" # Возвращаем текст успеха
    except Exception as e: # Если на этапе try что-то пошло не так (база упала, пароль не подошел)
        return f"Ошибка подключения к базе: {e}" # Возвращаем текст ошибки

@app.route('/')           # "Слушатель" главного адреса сайта (когда пользователь заходит на http://IP:5000/)
def home():               # Функция, которая срабатывает при этом заходе
    db_status = check_db() # Запускаем нашу проверку базы, описанную выше
    return f"<h1>Привет, Эдуард Евгеньевич!</h1><p>{db_status}</p>" # Выводим HTML-код на экран пользователю

if __name__ == "__main__": # Техническая строка Python: "Если этот файл запущен напрямую, а не импортирован..."
    app.run(host="0.0.0.0", port=5000) # ...то запустить веб-сервер. host="0.0.0.0" означает "слушать абсолютно все запросы извне", port=5000 — номер порта.
Используйте код с осторожностью.
3. Файл Dockerfile (Рецепт сборки контейнера с кодом)
Это инструкция для Docker, как превратить код программистов в готовый закрытый контейнер-образ.
dockerfile
# 1. За основу берем чистый образ Linux с уже установленным Python 3.9 (из зеркала Timeweb)
FROM dockerhub.timeweb.cloud/library/python:3.9-slim

# 2. RUN — выполни команду внутри собираемого контейнера. 
# Обновляем списки пакетов (apt-get update) и устанавливаем утилиты gcc и libpq-dev (они нужны, чтобы библиотека psycopg2 смогла скомпилироваться внутри Linux)
RUN apt-get update && apt-get install -y libpq-dev gcc

# 3. Создаем внутри контейнера папку /app и переходим в неё (все следующие команды будут выполняться в ней)
WORKDIR /app

# 4. Копируем файл со списком библиотек с нашего сервера (из текущей папки) внутрь контейнера (точка означает "текущая папка /app")
COPY requirements.txt .

# 5. Запускаем установку библиотек внутри контейнера. Флаг --no-cache-dir экономит место на диске
RUN pip install --no-cache-dir -r requirements.txt

# 6. Копируем сам файл с кодом (app.py) с сервера внутрь контейнера
COPY app.py .

# 7. CMD — главная команда, которая выполнится ТОЛЬКО тогда, когда контейнер будет запускаться. 
# Она запускает наш Python-скрипт. В прошлый раз тут была опечатка ("apppy"), из-за чего контейнер падал.
CMD ["python", "app.py"]
Используйте код с осторожностью.
4. Файл docker-compose.yml (Главный дирижер оркестра)
Скрипт Python — это один контейнер. База данных — это второй контейнер. Этот файл объединяет их в единую систему, управляет их запуском и настраивает сеть между ними.
yaml
services: # Список всех сервисов (контейнеров), которые мы хотим запустить одновременно

  db: # Название первого контейнера (мы назвали его "db")
    image: dockerhub.timeweb.cloud/library/postgres:15 # Не строим сами, а берем готовый официальный образ базы Postgres 15 версии из зеркала
    environment: # Переменные окружения (настройки, которые улетят внутрь базы при старте)
      POSTGRES_DB: my_db          # Создать внутри базы структуру с именем "my_db"
      POSTGRES_USER: postgres      # Создать главного пользователя "postgres"
      POSTGRES_PASSWORD: pass_key  # Установить для него пароль "pass_key"
    healthcheck: # Проверка "здоровья" контейнера. База запускается медленно, нам нужно знать, когда она РЕАЛЬНО готова принимать клиентов
      test: ["CMD-SHELL", "pg_isready -U postgres -d my_db"] # Команда, которая проверяет готовность базы
      interval: 5s   # Проверять каждые 5 секунд
      timeout: 5s    # Ждать ответа не больше 5 секунд
      retries: 5     # Если 5 раз подряд база ответит "я не готова", считать её сломанной

  python_app: # Название второго контейнера (наше Python приложение)
    build: . # Мы говорим Docker: "Тут нет готового образа в интернете. Возьми Dockerfile из текущей папки (.) и собери образ сам"
    ports: # Проброс портов (мост между сервером и контейнером)
      - "5000:5000" # Левый "5000" — порт на твоем сервере Timeweb. Правый "5000" — порт внутри контейнера. Благодаря этому ты сможешь зайти на сайт через браузер.
    depends_on: # Настройка очереди запуска
      db: # Наш Python зависит от контейнера "db"
        condition: service_healthy # ВНИМАНИЕ: запускать Python ТОЛЬКО тогда, когда контейнер базы пройдет проверку healthcheck и станет "здоровым". Это решает проблему, когда Python запускался быстрее базы и падал с ошибкой соединения.
